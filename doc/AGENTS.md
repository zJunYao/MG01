# AGENTS.md —— 项目协作指令

> 2026-10-22，与 GDD v0.3.2 同步。规则依据为 `doc/GDD-结构设计文档.md` 与 `doc/GLOSSARY.md`；Word副本仍为旧模板。

## 项目一句话

背包道具构筑与回合制战斗结合：轮到主角时整理道具、选择目标，确认后按构筑执行效果。正式游戏战后通过随机遭遇成长；当前Demo仅一场固定战斗。

## 当前 Demo 的关键约束

1. 背包7×5、备用区8槽（一件一槽）；五件道具合计14格，允许全部装入，不强制每轮换装。
2. 雷电法杖、雷电帽、泡泡、药水统一按最左列、再最上行排序；不采用固定武器先后，也没有恢复／防御优先阶段。
3. 符石只提供上下左右相邻增伤，不进入道具队列。队列只是执行展示，不可手动排序。
4. 药水实际恢复后销毁；满生命不使用、不销毁、不显示队列图标或跳过提示。放入背包不立即喝药。
5. 每轮主角→战士→盗贼→首领各行动一次。主角备战可免费调整与选目标，确认后锁定，不能写成全程自动战斗。
6. 目标切换按钮循环跳过死者；目标死亡后的自动转移从战士→盗贼→首领顺序开头查找，溢出伤害不转移。
7. 最后一敌死亡立即结束，后续药水等不执行、不消耗。主角死亡立即失败；不能为了播完动画继续扣血。
8. 确认后隐藏UIStage，采用HeroPreview场景位置进行战斗表现；保留角色行动条和生命／护盾信息，主角执行显示HeroAttackQueue。敌人行动后下次主角才重新打开UIStage。
9. 右下角按钮切换目标；物品旋转采用背包内双击90°。不要把按钮误接成旋转。
10. 界面／表现切换保持同一战斗状态；不是每次打开界面就初始化。是否真正加载独立Unity场景属于待定技术方案。
11. 哥布林战士每次行动二连击、每击3点，盗贼一次普通攻击、伤害4点；原攻击参数一起互换，已确认。战士第一击已击杀主角则不再执行第二击。

## 命名与绝对红线

1. 道具ID使用`snake_case`；具体ID、字段与技术结构以实际实现设计为准。
2. 战斗数值必须读配置表，禁止在业务代码写死伤害／护盾／恢复等值。现有预制体静态文字不是数值来源。
3. 涉及随机数时必须使用可播种的随机数生成器，方便复现；当前固定Demo不因此增加随机机制。
4. 改动规则前先更新GDD对应章节，新增术语同步术语表。
5. 不确定事实标注[VERIFIED]／[SYNTHESIZED]／[UNVERIFIED]；临时脚本推演不等于Unity实测。
6. Demo临时规则不自动推广至所有职业。不得擅自添加商店、局外成长、速度、法力、冷却或复杂首领阶段。

## 工作流

1. 动手前读取`doc/`下GDD与术语表，区分正式框架与仅Demo规则。
2. 先确认设计，再更新文档，再实现；一次处理明确的模块或功能范围。
3. 本次文档更新不代表已授权开发；根据用户明确要求推进代码与资源修改。
