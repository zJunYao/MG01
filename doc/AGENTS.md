# AGENTS.md —— 项目指令（给 AI agent 看的"宪法"）

> 使用说明：放进代码仓库根目录。只写 agent 自己发现不了的东西，不写长篇大论。
> GDD 定稿后，从 GDD 第 1、3 章摘"项目一句话"和"核心循环"填进来。

## 项目一句话

示例：一款背包构筑 + 回合制自动战斗的单机策略游戏：开局一个包，靠整理格子打出成吨伤害。

## 核心循环（agent 必须理解）
1. 回合间：商店购买 / 整理背包（旋转、摆放、合成）
2. 回合内：按背包配置自动触发武器技能，玩家不操作
3. 目标：用构筑出的 build 击败一波比一波强的怪物

## 技术栈
- 引擎：
- 语言：
- 战斗数值：必须走配置表（JSON / CSV），禁止 hardcode

## 目录约定（与 GDD 系统清单一一对应）

示例：
- `src/backpack/` 背包格子系统
- `src/items/` 物品定义与配置表
- `src/battle/` 回合战斗流程与结算
- `src/enemies/` 敌人与 AI
- `src/shop/` 商店与经济

## 命名约定
- 物品 id：`snake_case`，如 `iron_sword`
-

## 绝对红线
1. 战斗数值必须读配置表，禁止在代码里写死伤害 / 冷却
2. 随机数必须用可播种的 RNG（方便复现战斗回放查 bug）
3. 改动战斗规则前，先更新 GDD 对应章节
4. 不确定的事实标注 [VERIFIED] / [SYNTHESIZED] / [UNVERIFIED]，禁止一本正经地编

## Definition of Done（完成标准）
- [] 能编译 / 运行，无报错
- [] 涉及战斗的改动：附一次完整战斗的日志或截图，证明配置生效
- [] 新增物品 / 系统：在 GDD 与术语表中同步更新

## 工作流
1. 动手前先读 `docs/` 下的 GDD 与术语表
2. 按 story 实现，一次只做一个系统
3. 设计变更走"先改文档，再改代码"
