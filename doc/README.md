# 背包构筑回合制游戏 · 设计文档套件使用说明

## 这是什么
为你的「背包管理 + 回合制自动战斗」游戏准备的结构设计文档套件。
写完它，后续流程（灰盒原型 → agent 协作写代码 → 内容填充）就有了统一依据。

## 文件清单
| 文件 | 用途 | 什么时候写 |
|---|---|---|
| GDD-结构设计文档.md | 游戏结构设计的主文档 | 现在，按下面顺序写 |
| GLOSSARY.md | 术语表：统一所有名词定义 | 写 GDD 的同时维护 |
| AGENTS.md | 给 AI agent 的项目指令（放进代码仓库根目录） | 文档骨架定稿后，从 GDD 里摘录填写 |

## 写作顺序（按 ROI 排序）
1. GDD 第 1~3 章：一页概述 → 核心体验 → 核心循环图（约 1 天）
2. GDD 第 4 章：系统清单 + 优先级标签 + 依赖关系（约半天）——到这里骨架就立住了
3. GLOSSARY.md：把前两步出现的所有名词定死（一词一义）
4. GDD 第 5~7 章：核心系统的详细设计（随原型渐进填充，不要一次写完）
5. GDD 第 8 章：MVP 范围表（控制范围的刹车片）
6. AGENTS.md：填"项目一句话、核心循环、技术栈、红线"

## 标记说明
- → 需要你写的内容
- 示例：→ 参考粒度，定稿前删掉
- TBD → 暂时没想清楚，诚实标注，后续填

## 和后续流程的衔接
- **系统清单（GDD 第 4 章）= 代码模块划分**：一个系统对应代码仓库里一个目录，拆得干净 agent 并行写代码才不会打架
- **术语表 = agent 写代码时的命名依据**：先有统一名词，才有统一的变量名
- **Definition of Done（见 AGENTS.md）**：每个功能"能运行 + 留战斗日志/截图"才算完
